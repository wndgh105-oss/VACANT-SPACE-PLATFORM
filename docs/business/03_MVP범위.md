# 빈자리 — MVP 범위 정의

> 기준일 2026-09-03 · 이 문서는 **이번 버전에서 무엇을 만들고 무엇을 만들지 않는지**를 확정합니다.
> 코드베이스: `rental-platform` (Next.js 14 App Router + TypeScript + Prisma + PostgreSQL + NextAuth)

---

## 0. MVP의 목적

MVP는 사업을 운영하기 위한 시스템이 아니라, **다음 3가지 가설을 검증하기 위한 도구**입니다.

| # | 가설 | MVP가 검증하는 방법 |
|---|---|---|
| H1 | 예비 창업자는 "총 얼마인지"를 알면 상담 요청까지 진행한다 | 견적 화면 → 상담 요청 전환율 측정 |
| H2 | 창업자는 공간과 장비를 **묶어서** 사고 싶어 한다 | 견적에서 장비 패키지 포함 비율 측정 |
| H3 | 건물주는 단기 이용 조건으로 공실을 등록할 의사가 있다 | 등록 공실 수 / 실사 통과율 |

따라서 MVP는 **탐색 → 견적 → 요청 → 상태 관리**의 한 줄기를 끝까지 동작시키는 데 집중하고, 실제 정산·계약·결제는 만들지 않습니다.

## 1. MVP에 포함하는 것 (IN SCOPE)

### 1-1. 이미 구현 완료된 기반 (기존 18개 태스크)

| 영역 | 내용 | 상태 |
|---|---|---|
| 인증 | 이메일/비밀번호 회원가입·로그인 (NextAuth Credentials), 역할 선택 | ✅ 완료 |
| 역할 | 창업자(TENANT) / 건물주(LANDLORD) / 관리자(ADMIN) | ✅ 완료 |
| 공간 | 등록·수정·삭제, 사진 업로드, 상태(OPEN/CLOSED) | ✅ 완료 |
| 탐색 | 목록 조회, 지역·예산·기간·업종 필터 | ✅ 완료 |
| 신청 | 상담/예약 요청 제출, 상태 전이 (PENDING→CONTACTING→CONFIRMED/REJECTED) | ✅ 완료 |
| 즐겨찾기 | 관심 공간 저장 | ✅ 완료 |
| 장비 | 업종별 장비 패키지 마스터 CRUD (관리자) | ✅ 완료 |
| 관리자 | 사용자·공간·신청 관리 | ✅ 완료 |
| 테스트 | Vitest 단위/통합, Playwright 핵심 흐름 E2E | ✅ 완료 |

### 1-2. 이번 라운드에서 추가하는 것 (VACANT SPACE 확장)

| # | 기능 | 왜 MVP인가 |
|---|---|---|
| N1 | **디자인 시스템 전면 적용** (아이보리/차콜/테라코타, 모바일 우선, 카드형) | 심사·데모에서 "실서비스로 보이는가"가 신뢰의 전제 |
| N2 | **랜딩 페이지** — 문제 제기 → 비용 비교 → CTA | H1 검증의 입구 |
| N3 | **지도형 탐색** (목록 ↔ 지도 전환, 좌표 기반 자체 SVG 지도) | 지역 기반 탐색의 핵심 UX. 외부 지도 API 키 없이 자체 구현 |
| N4 | **필터 확장** — 주차·전기용량·가스·배수·즉시입주 | 업종 적합성 판단에 실제로 필요한 조건 |
| N5 | **공간 상세 확장** — 상권 요약, 추천 업종, 월 예상 비용 | 비교 판단 근거 제공 |
| N6 | **"내 예산으로 가능한 창업" 계산기** | 유입 후 첫 상호작용. 이탈 방지 훅 |
| N7 | **모듈형 장비 패키지 선택 UI** (카페/팝업/사무실/스터디, 품목 가감) | H2 검증의 핵심 |
| N8 | **통합 견적서** (공간+장비+기간, 정식창업 대비 절감액) | H1 검증의 핵심 |
| N9 | **장비 렌탈 파트너 역할** (PARTNER) + 파트너 대시보드 | 4번째 이해관계자를 데이터 모델에 반영 |
| N10 | **창업자 대시보드 확장** — 잔여 기간, 연장/이전 제안 | 여정 ⑧⑨ 구현 |
| N11 | **이전 소식 티저 페이지** — 힌트 카드, 흐린 지도, D-day, 공유 카드 | 차별화 기능. 데모의 하이라이트 |
| N12 | **건물주 대시보드 확장** — 공실 기간, 예상 수익 | 여정 구현 |
| N13 | **관리자 대시보드 확장** — 파트너·티저·콘텐츠 관리 | 운영 가능성 확인 |
| N14 | **신뢰 장치** — 본인인증 상태, 계약 체크리스트, 후기, 신고, 법률 안내 | 9-3 신뢰 장치 |
| N15 | **데모 배너 상시 노출** | 오해 방지 (필수) |
| N16 | **한국어 더미 데이터 시드** (실제 서비스처럼 보이는 공간 20+개) | 데모 품질 |
| N17 | **데모 영상** (Playwright 녹화 45~60초) | 4단계 산출물 |

## 2. 이번 버전에서 **하지 않는 것** (OUT OF SCOPE)

> 아래는 "못 해서"가 아니라 **의도적으로 제외**합니다. 각 항목에 제외 사유를 명시합니다.

### 2-1. 절대 하지 않는 것 (법적·윤리적 이유)

| # | 제외 항목 | 사유 |
|---|---|---|
| X1 | **실제 결제 / PG 연동 / 에스크로** | 전자금융거래법 검토 전. MVP는 "데모 요청"까지만. 자금을 일절 보관하지 않음 |
| X2 | **법적 효력 있는 전자 계약 체결·전자서명** | 표준 계약서가 법무 검토를 통과하지 않음. 계약 "진행 상태 표시"만 구현 |
| X3 | **실제 중개 행위** | 공인중개사법상 구조 미확정. MVP는 정보 제공 + 상담 요청 접수 |
| X4 | **실명 인증 / 신분증 / 사업자등록증 실제 수집** | 개인정보 수집 근거·처리방침 미비. 인증 **상태 표시**만 더미로 구현 |
| X5 | **인허가 가능 여부 자동 판정** | 법적 판단을 플랫폼이 단정하면 안 됨. **체크리스트 안내**만 제공 |
| X6 | **보험 실제 청약** | 대리점 계약 전. 안내 및 연결 요청만 |

### 2-2. 기술적으로 미루는 것 (다음 버전)

| # | 제외 항목 | 사유 | 예정 |
|---|---|---|---|
| X7 | 외부 지도 API (네이버/카카오/구글) | **API 키를 발급받을 수 없음.** 좌표 기반 자체 SVG 지도로 대체 구현 | P1 |
| X8 | 실제 상권 데이터 연동 (공공 API) | API 키 미확보. 시드 데이터에 상권 요약을 **더미로 삽입**하고 출처를 "예시"로 명시 | P1 |
| X9 | 실시간 채팅 / 알림 (푸시·SMS·카카오톡) | 발신번호 등록·비즈메시지 계약 필요 | P1 |
| X10 | 이메일 발송 (가입 인증·알림) | SMTP 계정 미확보. 콘솔 로그로 대체 | P1 |
| X11 | 소셜 로그인 (카카오/네이버) | OAuth 앱 등록 필요 | P1 |
| X12 | 이미지 CDN·리사이징·최적화 | 로컬 업로드 + 플레이스홀더로 충분 | P1 |
| X13 | 파트너 셀프 온보딩 및 정산 | 정산 로직은 실거래 이후 설계 | P2 |
| X14 | 상권 추천 알고리즘 / ML | 데이터가 없음. 규칙 기반 추천으로 대체 | P2 |
| X15 | 다국어 (i18n) | 한국 시장 단독 타깃 | P3 |
| X16 | 모바일 네이티브 앱 | 반응형 웹으로 충분 | P3 |
| X17 | 예약 캘린더 / 중복 예약 잠금 | 상담 기반 수동 확정으로 충분 | P1 |
| X18 | 리뷰 평점 집계·정렬 알고리즘 | 후기 작성·표시까지만 | P1 |

| # | 제외 항목 | 사유 |

## 3. "가짜로 처리한 것" 명시 목록

프롬프트 요구에 따라, **실제가 아닌 것을 실제인 척하지 않기 위해** 아래를 명시합니다.

| 항목 | 실제 상태 | MVP 구현 |
|---|---|---|
| 결제 | ❌ 없음 | 화면에 "데모 결제" 배지, 금액만 계산 |
| 계약 | ❌ 없음 | 상태 값만 존재 (요청/상담중/확정) |
| 지도 | ❌ 외부 API 미사용 | 위경도 좌표를 SVG 평면에 투영한 자체 지도 |
| 상권 데이터 | ❌ 공공 API 미연동 | 시드에 하드코딩된 예시 텍스트 ("예시 데이터" 라벨) |
| 본인 인증 | ❌ 실제 인증 없음 | `verified` 불리언 필드, 관리자가 수동 토글 |
| 사진 | ❌ 실제 매물 사진 아님 | 자체 생성 추상 SVG 플레이스홀더 |
| 알림 | ❌ 발송 없음 | 서버 콘솔 로그 + 화면 내 알림 목록 |
| 보험·인허가 | ❌ 연계 없음 | 안내 문구 + 상담 요청 체크박스 |

## 4. 완료 판정 기준 (Definition of Done)

MVP는 아래를 **모두** 만족할 때 완료로 봅니다.

- [ ] `npx tsc --noEmit` 통과
- [ ] `npm run lint` 통과
- [ ] `npm run build` (production) 통과
- [ ] Playwright E2E: 창업자 탐색→견적→요청, 건물주 등록→승인, 이전 티저 생성 흐름 통과
- [ ] 375px(모바일) / 1280px(데스크톱) 에서 레이아웃 깨짐 없음
- [ ] 모든 이미지 alt, 폼 label, 포커스 링, 대비 4.5:1 이상
- [ ] 데모 배너가 모든 페이지에 노출
- [ ] README만 보고 새 환경에서 실행 가능
- [ ] 데모 영상 `demo.mp4` 재생 가능
