# 건물주(임대인) 화면 설계 스펙

- 작성일: 2026-09-02
- 관련 문서: [모두의창업_지원서_초안.md](../../../../모두의창업_지원서_초안.md), [2026-09-02-tenant-screens-design.md](2026-09-02-tenant-screens-design.md)
- 범위: 단기 임대형 모듈 창업 플랫폼의 **건물주(임대인) 측 MVP 화면**만 다룬다. 창업자 측 화면은 [2026-09-02-tenant-screens-design.md](2026-09-02-tenant-screens-design.md)에서 이미 정의했으며, 운영자(관리자) 측 화면은 별도 스펙으로 분리한다.

## 1. 배경 및 목표

건물주가 보유한 공실을 플랫폼에 등록하고, 창업자 측에서 들어온 신청을 확인할 수 있는 최소 기능의 화면을 정의한다. 창업자 측 스펙과 동일한 "공실" 데이터 모델을 공유하는 것을 전제로 한다.

## 2. 범위 결정 사항

| 항목 | 결정 |
|---|---|
| 장비 패키지 관리 주체 | 플랫폼(운영진)이 업종별 표준 패키지를 미리 제공, 건물주는 등록 시 켜고 끄는 선택만 가능 |
| 신청 열람 방식 | 건물주가 자신의 공실에 들어온 신청 리스트를 직접 조회 (운영진 필터링 없이 실시간 노출) |
| 계약 종료(연장/이동/철수) 처리 | MVP 제외. 공실 등록과 신청 확인까지만 다룸 |
| 신청 상태 변경 | 건물주는 상태를 읽기 전용으로 조회만 가능, 변경은 운영자 전용 기능 |
| 결제/정산 | MVP는 오프라인 처리, 건물주 화면에 결제 UI 없음 |

## 3. 정보구조 (Sitemap)

채택 접근: **대시보드 중심형**. 여러 공실을 동시에 관리하는 건물주의 실제 사용 패턴에 맞추고, 창업자 측 "마이페이지 신청 현황"과 대칭 구조를 이뤄 데이터 모델·컴포넌트 재사용성을 높인다.

```
건물주 회원가입/로그인
        │
        ▼
내 공실 대시보드(홈) ──(+ 새 공실 등록)──▶ 공실 등록/수정 폼
        │
        ▼(카드 클릭)
공실 상세(건물주 관리자 뷰) ──(수정하기)──▶ 공실 등록/수정 폼(값 채워짐)
        │
        ▼(전체 신청 보기)
공실별 신청 리스트
```

## 4. 화면별 상세

### 4.1 건물주 회원가입 / 로그인
- 이메일 + 비밀번호. 창업자 측과 동일한 가입 폼을 재사용하되, 계정 유형을 "건물주"로 구분

### 4.2 내 공실 대시보드 (홈)
- 상단: "+ 새 공실 등록" 버튼
- 공실 카드: 썸네일, 주소(간략), 상태(공개중/마감), 월 임대료, 신청 건수 배지
- 카드 클릭 → 공실 상세(관리자 뷰)로 이동
- 등록된 공실이 없을 때: 빈 상태 안내 + 등록 버튼

### 4.3 공실 등록 / 수정 폼
- 기본 정보: 주소, 면적, 사진 업로드(다중), 월 임대료, 보증금
- 계약 조건: 계약 가능 기간 옵션(복수 선택 가능, 예: 2/4/6개월 중 제공 가능한 것 체크)
- 업종 선택: 가능한 업종(카페/소매·팝업/기타) 체크 → 선택 시 해당 업종의 표준 장비 패키지가 자동 미리보기로 노출. 패키지 내용 자체는 편집 불가, 포함 여부만 켜고 끔
- 저장 검증: 주소·임대료·사진 1장 이상 필수

### 4.4 공실 상세 (건물주 관리자 뷰)
- 창업자 측에 노출되는 상세 페이지와 동일한 정보를 미리보기로 표시
- "수정하기" → 등록 폼(값 채워진 상태)으로 이동
- 하단: 최근 신청 3건 요약 + "전체 신청 보기" 링크

### 4.5 공실별 신청 리스트
- 신청자 이름, 연락처, 희망 계약기간, 희망 시작일, 요청 메시지, 신청일
- 정렬: 최신 신청순
- 상태 배지는 창업자 마이페이지와 동일한 값(대기중/연락중/확정/반려)을 표시(읽기 전용)

## 5. 예외 / 엣지 케이스

- **등록된 공실이 없을 때**: 대시보드 빈 상태 + 등록 유도
- **필수 정보 누락 후 저장 시도**: 저장 차단, 누락 필드 강조
- **신청이 있는 공실을 수정하려 할 때**: "이미 N건의 신청이 들어와 있습니다. 조건 변경 시 신청자에게 혼선이 있을 수 있어요" 경고 후 계속 여부 확인(차단하지 않음)
- **공실 상태가 "마감"인 경우**: 마감 전환은 운영자 전용 기능(§6 제외 항목)이므로 건물주 화면에서는 읽기 전용 표시만
- **신청 리스트가 비어있는 공실**: "아직 들어온 신청이 없어요" 안내
- **표준 장비 패키지가 없는 업종 선택**: "이 업종은 장비 패키지 준비 중" 문구로 대체, 등록 자체는 허용
- **사진 업로드 부분 실패**: 실패한 파일만 에러 표시, 나머지는 정상 진행
- **동일 주소 중복 등록**: MVP에서는 별도 검증 없이 허용(운영자 측에서 추후 수동 확인)

## 6. 이번 스펙에서 제외한 것 (다음 스펙 후보)

- 계약 연장/이동/철수 처리 화면 → 운영자 스펙에서 다룸
- 신청 상태 변경 액션(대기중→연락중→확정 등) → 운영자 전용 기능
- 결제/정산 화면
- 장비 패키지 직접 등록/편집 기능(건물주는 선택만 가능)
- 다중 담당자/법인 계정 권한 분리
- 공실 통계·수익 리포트 화면

## 7. 다음 단계

- 이 스펙 승인 후, 구현 계획은 별도 writing-plans 절차로 작성한다.
- 운영자(관리자) 측 화면은 별도 브레인스토밍 세션에서 독립된 스펙으로 진행한다. 특히 "신청 상태 변경", "계약 확정/마감 전환", "장비 패키지 마스터 관리"가 핵심 기능이 될 것으로 예상된다.
